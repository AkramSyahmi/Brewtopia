# BREWTOPIA: guide for Claude Code

A cosy pixel-art barista game set in a Malaysian café ("A Malaysian café story"). The player
is a new barista: customers order, the player makes each drink by hand (grind, tamp, pull
the shot, steam milk, latte art, syrups and toppings), the drink is scored, the mentor gives
one tip, and four regulars become friends with stories of their own. It's an entry for the UMPSA ×
HUAWEI UXHMAC 2026 competition (Android).

- Engine: **Godot 4.7.2** (`android/.build_version`). Renderer `mobile`. Viewport **1280×720**, stretch `canvas_items`.
- Entry point: `run/main_scene = res://scenes/ui/title_screen.tscn`.
- Autoload: `Audio` → `scripts/core/audio.gd` (the only one).
- `config/name` is still `"UXHMAC 2026"`, and the Android package is `com.uxhmac.game`.

Longer explanations: `PROJECT_HANDOVER.md`. Manual test procedure: `TESTING_CHECKLIST.md`.

## Architecture

There are only **two scenes**, each with one root `Control` and one script. **Everything else (UI, layout,
equipment, the café) is built in code at runtime.** There are no editor-authored node trees and no `.tres` themes.

Runtime layering (CafeShift): layer 0 = `CounterScreen` / `EspressoStation` / result strip;
CanvasLayer 1 = HUD, order ticket, speech bubble, objective panel; CanvasLayer 2 = modal dim, Recipe
Book, Shop, Menu (plus the station's steam and latte-art popups); CanvasLayer 3 = credits. The counter
and station are siblings that are **shown and hidden**, not scene changes.

## Gameplay (brief; details in PROJECT_HANDOVER.md)

- **Flow:** title → `cafe_shift.tscn` → per order: customer walks in → intro dialogue → `Step.BAR` →
  drag drink to SERVE → `EspressoStation.served(drink)` → `CafeShift.on_served` → `DrinkModel.evaluate`
  → RESULT (score <40 = "Failed Order", remake) → Continue (friendship, reaction) → next order →
  SUMMARY (wage, tips, XP, Shop, Next day).
- **Station state:** `PfState {EMPTY, DOSED, TAMPED, USED}`, `ShotState {IDLE, EXTRACTING}`,
  `MilkState {EMPTY, COLD, STEAMED}`, `SteamState {CLOSED, OPEN, STEAMING}`. Two portafilters, two group
  heads, max two cups.
- **Grind/dose:** hold the grinder with a portafilter in the `fork` zone (4 g/s). Grind runs 1 (fine) to 10, the day starts at 8, and the ideal is 5.
- **Tamp:** tap the tamper while a dosed portafilter is on the `mat`. Pass/fail only.
- **Shot:** tap the locked portafilter to start and stop. Flow comes from `EspressoModel.flow_rate`; simulated time runs at ×2.
- **Milk:** drag the pitcher to the fridge (cold) → steam zone (popup: hold = heat, lower = more foam) → onto a cup.
  `milk_temp` / `milk_foam` always hold the real values; `milk_heat()` gives the band: cold (< `COLD_MAX_C` 20 °C),
  warm (20–39 °C, tag WARM, state still `COLD`), steamed (≥ `STEAMED_MIN_C` 40 °C, state `STEAMED`). The tag, hover text,
  pour message, cup drawing (`CupLiquid`) and latte-art trigger all follow it. Only steamed milk poured into a ceramic `cup`
  starts latte art. Any milk can be poured; the score judges the real temperature against the recipe.
- **Toppings page:** cups with coffee move to 2 slots; tap a syrup = +1 pump; tap a topping = add once. The **Undo**
  button (topping page only) takes back the current cup's last pump or topping, newest first (`undo_extra()`, using the
  per-cup `Cup.extras_log`; `drink.syrups` / `drink.toppings` stay the source of truth). The log goes with the cup, so serving,
  discarding or a new order clears it. `extras_cup()` = the cup taps and Undo act on. On guided orders (`guide_on`), a pump past
  the recipe amount or an extra not in the recipe says "… Tap Undo." (never on no-assist or vague orders: no spoilers).
- **Discard:** dropping a cup on the `rack` / `iced_stack` zone calls `discard_cup()` → `remove_cup()`. All per-drink
  state lives in the `Cup` object, so the whole drink goes with it (no serve, score or save). A fresh cup comes from the rack.
- **Scoring:** shot = 0.2 dose + 0.4 yield + 0.4 time (time judged on `pace_s`, which comes from grind and tamping);
  milk drinks mix shot / milk / art; accuracy = 100 minus penalties; **score = quality × accuracy / 100**.
  Service (patience) only affects tips. Patience drains in `CafeShift._process` while `waiting`, except while the Recipe Book
  or the latte-art popup is open (and while the Menu pauses the game).
- **Progression:** XP = Σscores/5, level = 1 + XP/60, recipes unlock by `unlock_level`, day 2+ generated
  by `DayPlan` (seed `day × 7919`). Upgrades and decor in the Shop.
- **Save:** `user://brewtopia_save.json` (written via a .tmp file, then renamed). Keys: `money, xp, day, upgrades{shot_timer,
  steam_control, tip_jar}, friends, story_seen, decor, recipes_seen, finale_seen`. Audio settings are in
  `user://settings.json`. **The save is written only at the day summary** (`CafeShift`: `save.day = shift_day + 1`, then one
  `SaveGame.write`), plus Shop purchases and the finale, which happen after it. During a day, money, XP, friendship, story beats
  and `recipes_seen` change only in memory, so quitting mid-day restarts that day exactly as it began (same `DayPlan`), and
  quitting on the summary keeps the finished day. `shift_day` is the day being played (HUD clock, summary heading);
  `save.day` is already the next day once the summary is up. The Menu says "Leaving now restarts today." during a day.

## Dependencies that break silently

- **Signals:** `EspressoStation.served(drink)` → `on_served`; `.changed` → `refresh_hint` (and the station's own `refresh_guide`);
  `.message(text)` → `show_feedback`; `LatteArtPanel.finished(score)` → `on_art_finished`;
  `UpgradeShop.bought` → `apply_upgrades`/`set_decor`/`refresh_hud`. `shot_finished`, `milk_frothed` and the `Bar3D`
  signals have no listeners. `Audio` connects every `BaseButton.pressed` to the click sound.
- **Drink dictionary** (the station → scorer contract): `dose, grind, tamped, yield, time, cup, milk_temp (-1 = none),
  milk_foam, art, art_result, syrups{}, toppings[], ice, shot, green_g, shot_rating`. `art_result` is only present when
  the latte-art round ended without a pour (`"skipped"` / `"timeout"`, with `art` = 0.0).
- **Latte art** (`LatteArtPanel`): each `start()` ends exactly once (`done` flag, `session` counter): by the pour, the Skip
  button, or the `TIMEOUT_S` (30 s) timeout counted on `t` in `_process`, so it pauses with the game. `finished(score)` is
  unchanged; the panel's `result` says how it ended.
- **Station coordinates:** the world is a `Node2D` at scale 2 (640×360 base px per page, toppings page at base x 640).
  `local(p) = (p - world.position) / 2`. Drop targets are `SnapZone`s from `build_zones()`, found by a physics point
  query. Drops resolve on one anchor point per item: portafilter basket centre (`PF_BASKET`), cup centre, pitcher centre.
  `press()` checks targets in priority order: cups → toppings (page 1) → pitcher → portafilters → tamper → racks → brew → grinder.
  `_input` force-ends drags on mouse-up.
- **Art-measured constants:** `GROUP0/1_HEAD_X`, `GROUP_HEAD_BOTTOM`, `PF_RIM`, `PF_BASKET`, `GRINDER_*`, `CUP_STAND_Y`,
  `CUPS[*].anchor/inside/rim_y`, `FRIDGE_DOOR`, `PitcherMilk.CENTRE`, and the "keep in step" constants in
  `tools/make_topping_art.gd`. They are pixel positions in specific PNGs.
- **Tutorial:** `objective()` / `objective_steps()` / `guide_rect()` work out the step from live state; moving
  equipment means updating its guide target. Assist level is per order (data `"assist"`, not a player setting):
  `"full"` shows `objective().full` (target values) plus the outline and arrow (`station.guide_strong`); `"hints"` shows
  `objective().text` (no exact measurements) plus the outline only; `"none"` shows only the feedback line. Keep panel lines
  at 2 lines or fewer (16 px `numbers()` font in 386 px) so the panel doesn't grow over the grinder or iced cups.
- **Node lookups by name:** `SnapZone` child `Snap`; Kenney person children `Body` and `Emote`; grinder/machine children in
  `Bar3D` (`GroundsStream`, `LCD`, `ScaleLCD`, `GrindButton`, `Dial`, `BrewButton`).
- **Scene changes:** only `title_screen.tscn` ↔ `cafe_shift.tscn` (`change_scene_to_file`).

## Visual style (keep it)

- Warm café pixel art: espresso browns (`#36251D`, `#3B2314`), cream (`#F5E7CA`, `#FBF4EA`), wood (`#C98E55`, `#8A4A26`),
  gold accents (`#F2C14E`, `#FFE066`), green for success (`#A8E07A`), dark-brown outlines (`#3A2416`), not black.
- UI = 9-slice **wood/cream signs** via `PixelUI.frame()`, `cream_panel()`, `wood_pill()` (margins 15/15/15/18 for signs,
  12/9/12/12 for badges). Brown gold-rimmed sign for in-game info, cream sign for popups, wood planks for buttons.
- **Fonts:** Pixelify Sans Brew (600 body, 700 headings/buttons): Pixelify Sans with wider C and c openings, a square-topped 5 and no
  fi/fl/ff ligatures (`tools/patch_pixelify.py`; `PixelUI.FONT`). **Any number the player must read uses
  `PixelUI.number_label()`** (Silkscreen digits plus Pixelify fallback, size a multiple of 8). Big score: Silkscreen Bold 40.
- **Pixel density:** world (station and 3D café) 2 screen px per art px; UI frames and icons 3 px; latte art 6 px. Nearest-neighbour
  filter, no mipmaps for pixel art. In-world labels use `pixel_text()` (2× size, 0.5 scale).
- The toppings page is the quality benchmark. Equipment must be detailed sprites, never placeholder rectangles.
- Overlays above the station need `MOUSE_FILTER_IGNORE`; modals sit behind a click-blocking dim. New CanvasLayers
  need the theme set (`ui_layer()`), because themes don't cross layers.

## Development rules (from the user; mandatory)

1. Visual work never changes unrelated gameplay (a machine redesign doesn't touch extraction, a grinder redesign doesn't touch dosing).
2. Small targeted edits: no script rewrites, scene replacement, node/signal renames, public signature changes or reorganising files.
3. Before moving anything, check hitboxes, SnapZones, snap points, transforms, input handlers and anchors. Move the sprite and its zone together.
4. Keep visuals separate from logic, with no duplicate state. No large refactors without approval.
5. Stay in the established style: no generic modern UI, blur, gradients, random palettes or oversized panels.
6. Scoring, accuracy, extraction/milk evaluation, patience, friendship and money change only with explicit approval.
7. Save schema: never rename keys; explain any migration before doing it.
8. Work in phases: inspect → plan → risks → implement one phase → validate → report → wait for approval.
9. Test after changes; never claim something was tested when it wasn't.
10. Git: check branch/status/log first. Never force push, delete branches, reset history, discard changes, or push without permission.
11. Ask when uncertain.
12. Report after each change: files modified, what changed, what was preserved, tests run, tests not run, remaining issues.

Project-specific rules:
- **Don't run art or audio generators without asking.** `tools/make_topping_art.gd` is the source of most station sprites
  and ignores `assets/art/KEEP.txt`. `tools/render_sprites.gd` would overwrite `milk_fridge.png`, `tools/gen_iced_art.gd`
  would overwrite `ice_bin.png`, and `tools/gen_audio.gd` overwrites every SFX file. Font tools:
  `tools/make_digit_font.gd` overwrites `BrewtopiaDigits.ttf`; `tools/patch_pixelify.py` (Python + fontTools) overwrites
  `PixelifySansBrew.ttf`. Don't edit the generated fonts by hand: change the tool and re-run it.
- When art changes size or layout, re-measure the art-measured constants in the same change.
- Data JSON keys are read by code: content edits are fine, key renames aren't. Changing `DayPlan`'s seed or what `recipes_seen` means
  changes every player's future days.
- The working tree contains editor-made CRLF-only `.import`/`project.godot` changes (no `.gitattributes`) and a real
  `colormap.png.import` compression change. Don't stage, commit or revert them unless the user decides. Stage only files you changed,
  and branch off `main` before committing.

  recipe has `"latte_art": true`. All current ceramic-cup milk recipes have the flag (Mocha's was added on
  feature/adeeb-brewtopia-work), so keep the two in step when adding recipes.
